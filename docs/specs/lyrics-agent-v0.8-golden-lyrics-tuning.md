# 写歌词 Agent v0.8 金曲奖级调优方案

## 目标

v0.8 只调写词质量，不改前端、OpenAPI、数据库、音乐、封面或视频链路。目标是把 LyricsAgent 从“能写燕云相关歌词”推进到“能写有作品感、能被听懂、值得继续打磨的歌”。

本轮保持现有知识库检索和注入方式不变。知识库仍提供燕云事实、人物关系、场景气质和可用意象，但不能变成歌词里的资料清单。

## 生产链路变化

- `CreativeBriefAgent` 从 v0.7 升级到 v0.8。
- 新增核心判断字段：
  - `song_core`
  - `singer_voice`
  - `listener_target`
  - `emotional_engine`
  - `chorus_job`
  - `avoid_direction`
- 旧字段如 `creative_core`、`song_thesis`、`chorus_function` 继续保留，但只作为辅助。
- `LyricsAgent` 优先完成一首歌，而不是逐条满足规则。
- `QualityEvaluationAgent` 增加 Prompt + 歌词联评口径，但不作为最终评委。

## 评审原则

评审必须一起看：

1. 用户原始输入。
2. 知识库召回。
3. CreativeBrief。
4. LyricsAgent system/user prompt。
5. 最终歌词。

不能只看歌词孤立评价，也不能只看 Prompt 是否写得漂亮。

## 一票否决

- 听不懂这首歌在唱什么。
- 像散文、剧情简介、设定介绍。
- 副歌没有功能。
- 只是堆燕云名词。
- 漂亮但空。
- 用户故事被丢失。
- 完全不可唱。

## 结论标签

- `金曲潜力`：有明确作品核，值得继续打磨。
- `可用但不够顶`：用户可能接受，但不能作为调优成功样本。
- `不通过`：方向失败，需要重写。

## 失败归因

- `用户输入太模糊`
- `知识库召回干扰`
- `CreativeBrief 方向错误`
- `LyricsAgent Prompt 规则过载`
- `LyricsAgent 执行弱`
- `QualityEvaluation 没拦住`

## 首批 A/B 结论

首批 6 条真实 DeepSeek A/B 已完成，完整 Prompt 与完整歌词只保存在 ignored 的 `build/reports/lyrics-agent/`。
可提交的脱敏评审摘要保存在 `knowledge-base/lyrics-agent-v0.8-ab-review-summary.json`。

结论：

- v0.8 初版只赢 1/6，不进入 24 条扩大评测。
- v0.8 的优势是歌曲命题更清楚，副歌功能更明确。
- v0.8 的主要问题是把 `song_core` 直接唱成显眼口号，削弱了真实细节、暧昧空间和人物质感。
- v0.7 在多条样本中胜出，是因为它保留了更奇异、更生活化、更像真实玩家记忆的声音装置。

v0.8.1 调整方向：

- `song_core` 作为暗中统领，不直接改写成反复喊的主题句。
- `chorus_job` 通过具体声音、动作、物件、句式变奏或意象回环完成，而不是只重复题目或结论。
- 每首歌至少保留一个不那么标准但真实的细节，来自用户输入或知识库。
- 轻量、亲密的输入避免过度解释；粗粝题材避免空喊、泛化反叛和无必要粗口。

## v0.8.1 A/B 结论

v0.8.1 已复跑同一批 6 条，脱敏评审摘要保存在 `knowledge-base/lyrics-agent-v0.8.1-ab-review-summary.json`。

结论：

- v0.8.1 胜出 3/6，明显优于 v0.8 初版的 1/6，但仍未达到扩大到 24 条的门槛。
- 胜出样本集中在：角色温情、烟火市井、九流门粗粝题材。
- 失败样本集中在：地点怀念、小人物出手、表面轻快后劲酸。
- 核心问题已经从“口号化”收敛为“有些题写得太满、太用力、太正确”。

v0.8.2 调整方向：

- 地点怀念类歌曲要敢于少写，只选一个小感官仪式或重复物件反复变义。
- 小人物/不厉害题材保留笨拙、温暖和人间尺度，避免夸张成断骨血战或英雄受难。
- 表面轻快后劲酸的歌，优先找无害口头禅、玩笑、动作或小约定，让它在后半首变酸。
- 如果用户输入或旧版输出里已经有一个奇异具体的声音装置，优先保留并深化，不要替换成更普通的主题句。

## v0.8.2 全量 6 条回归结论

v0.8.2 在 3 条失败题小测中胜出 2/3，但完整 6 条回归只胜出 1/6，未达到扩大到 24 条的门槛。
这说明问题不是某个单点规则缺失，而是 Prompt 仍然偏“纠正型”和“规则型”，会在随机生成中把模型推向更安全、更平整、更普通的歌词。

v0.8.3 调整方向：

- 不继续累加规则，改为更短的写作优先级：一个私人声音装置、一个具体情绪发动机、一个副歌变义方式。
- 如果用户输入、知识库或 Brief 中出现更鲜活的私人装置，例如“笨啊你”“再喝一碗”“茶碗一响”，优先围绕它写。
- 内部至少构思两个可重复 hook 或声音装置，选择更私人、更不泛用、更具体、更能二次变义的那个。
- 副歌宁可短、准、反复、有变义，也不要为了完整而塞满解释。
- 如果一个规则会让歌词更工整但更没生命，放弃这个规则，保留生命。

## v0.8.3 / v0.8.4  targeted 复评结论

v0.8.3 在清河地点怀念、小人物出手、轻快后劲酸 3 条 targeted 样本中胜出 2/3：

- 清河怀念：v0.8.3 的“茶还热着吗”比 v0.7 更私人、更少铺陈，结尾“凉了，早就凉了”有真实刺痛感。
- 轻快后劲酸：v0.8.3 的“走啊，去看看”是目前最接近目标的结果，同一句口头禅自然变义。
- 小人物出手：v0.8.3 失败，误把摇滚能量转成“拳套、沙袋、巷子拳击”等现代道具，破坏燕云归属感。

v0.8.4 只针对“小人物出手”补边界：曲风只能影响节奏、能量、声口和句子颗粒度，不能引入现代场景或现代物件。单条复测显示：

- 现代道具漂移已修复，歌词回到泥路、斗笠、旧剑、护人等燕云可成立的生活材料。
- 但副歌仍偏普通，“还没倒 / 挥刀 / 咆哮”是可用热血表达，不是金曲级私人记忆点。
- 因此 v0.8.4 是边界修复，不是质量突破；暂不扩大 24 条。

当前判断：继续无限追加 Prompt 规则的边际收益正在下降。下一步更可能有效的方向是让 Agent 在生成前更明确选择“私人弱点标记 / 小承诺 / 反复错误 / 口头习惯”这类非口号装置，或引入轻量候选选择机制，而不是继续加通用约束。

## v0.8.4 全量 6 条回归结论

v0.8.4 完整 6 条回归结果为 3/6，与 v0.8.1 持平，仍未达到扩大 24 条的门槛。

胜出样本：

- 小人物出手：`一、二、三` 倒数装置有效，修复了 v0.8.3 的现代拳击道具漂移。
- 市井烟火：旧灯从环境物件推进为情感容器，视角比 v0.7 更统一。
- 轻快后劲酸：跑调旧歌、拍肩口头禅和“走吧”变义，是目前最接近目标的方向。

失败样本：

- 寒香寻：v0.7 的“灯还亮着”更克制、更贴寒姨等待；v0.8.4 情感动作偏泛。
- 清河怀念：v0.8.4 的“旧衫”文学感强，但副歌不像能被普通用户马上记住。
- 九流门：v0.8.4 太干净、太规整，削弱了底层江湖的脏乱和危险。

结论：Prompt-only v0.8 线已经能偶发产出优秀私人口头禅和声音装置，但不稳定；它会在原始、粗粝、地点怀念等题材上过度清洁或过度文学化。下一步不建议继续无限加规则。

建议下一阶段二选一：

1. **轻量候选选择机制**：只在写词链路内部增加一次低成本选择，先让模型提出 2 个副歌装置 / 进入角度，再选择更私人、更可唱、更贴燕云的一个写完整歌词。
2. **单调用极简 Prompt 回退**：如果必须保持一次 LLM 调用，则删掉大部分题材专门规则，只保留 `song_core`、私人声音装置、燕云边界、可唱性和质量自检，避免 Prompt 过载。

## v0.9 轻量候选选择方案

v0.9 采用轻量 `LyricsCraftPlan` 路线，不继续在写词 Prompt 里堆规则。

适用范围：

- 只用于首轮 `INSPIRATION` 写词。
- 不用于 `POLISH` / `CONTINUE`，避免润色和续写再次变慢。
- 暂不用于 `LYRICS` 填词成歌，避免改坏用户已有歌词。

运行方式：

1. `CreativeBriefAgent` 仍先判断燕云创作边界和歌曲入口。
2. `LyricsCraftPlanner` 只选择写法，不生成完整歌词。
3. CraftPlan 输出 `song_thesis_guard`、`selected_device`、`selected_angle`、`chorus_mechanism`、`yanyun_boundary_guard`、`rejected_alternatives`。
4. `LyricsAgent` 最终写词只围绕 `selected_device + selected_angle + chorus_mechanism` 展开。
5. CraftPlan 失败时降级到 v0.8.4 直写，不阻断用户创作。

配置：

```text
LYRICS_CRAFT_PLANNER_ENABLED=true
```

脱敏评审摘要：

```text
knowledge-base/lyrics-agent-v0.9-full6-review-summary.json
```

完整 Prompt 和歌词仍只保存在 ignored 的 `build/reports/lyrics-agent/`，不得提交。

## v0.9 首批 6 条回归结论

v0.9 完整 6 条回归结果为 4/6，达到进入 12 条中样本评测的门槛，但还不能直接扩大到 24 条。

胜出样本：

- 寒香寻：`少东家，饭好了` 把角色从漂亮怀念拉回不羡仙日常和不可抵达的回声。
- 清河怀念：`再坐会儿` 比红线人物漂移更贴“新手村离开后才想回去”的用户意图。
- 小人物出手：`拍掉膝盖的沙，再来` 比泛热血更有人味。
- 轻快后劲酸：`走啦，下次再聚` 完成了从玩笑到刺痛的变义。

未胜出样本：

- 市井烟火：v0.9 有统一装置，但不如 v0.7 克制自然，部分场景说明感偏重。
- 九流门：v0.9 已修复 v0.8.4 过度清洁问题，但仍不如 v0.7 的脏乱、危险和底层噪音。

关键风险：

- CraftPlan 额外增加一次 DeepSeek 调用，首批观测耗时约 `6.6s-39.1s`，只适合首轮灵感写词，不应进入润色/续写。
- 九流门、鬼市、底层江湖等粗粝题材仍需要更锋利的选择压力，避免回到“老子不输”这类摇滚套话。
- 市井烟火、地点怀念等低声量题材需要避免解释过度，保留空白和自然生活口气。

下一步：

- 先跑 12 条中样本。
- 若 v0.9 至少 8/12 胜出，且至少 3 条达到 `金曲潜力`，再扩大到 24 条。
- 若 12 条不达标，优先调 CraftPlan 的选择压力，不继续在 LyricsAgent 里堆规则。

24 条完整评测已完成，脱敏摘要为：

```text
knowledge-base/lyrics-agent-v0.9-full24-review-summary.json
```

完整评测结论：

- v0.9 胜出约 18/24，超过 16/24 门槛。
- 估算至少 12 条具备 `金曲潜力` 或继续打磨价值。
- v0.9 在以下类型上明显变稳：
  - 地点怀念：清河、新手村、不羡仙。
  - 玩家故事：不厉害但出手、退坑朋友、不是主角但想被记住。
  - 玩法转译：偷师从机制变成“偷半招”的练习与自尊。
  - 底层/九流：从过度清洁转向更有噪音和市井危险。
  - 小意象：清河雨中旧铃、路边灯、豆花吆喝等。
- v0.9 仍输给 v0.7 的类型：
  - 寒香寻：部分 rerun 中 v0.7 更克制、更角色化。
  - 反宏大守护：v0.7 的“山河再大，大不过一个人”更锋利。
  - 失败者尊严：v0.7 的直白句更有记忆点。
  - 少数角色歌：v0.9 会把角色特殊性变成通用物件。

当前产品决策建议：

- v0.9 可以作为首轮 `INSPIRATION` 的默认方向。
- 暂不用于 `POLISH` / `CONTINUE` / `LYRICS`。
- 不再继续向 LyricsAgent 主 prompt 堆通用规则；后续只调 CraftPlan 的选择策略。
- 需要单独跟踪 CraftPlan 的耗时，因为它增加了一次 DeepSeek 调用。

下一轮可微调点：

- CraftPlan 遇到用户原句本身很强时，应优先保留用户原句作为 device，而不是另造新 device。
- 角色歌必须选择角色独有动作或物件，不能退回“灯、酒、梨花”等通用诗性材料。
- 反宏大题材避免“我不退、最后一回”这类熟悉英雄语。
- 粗粝题材允许噪音与脏乱，但是否允许粗口需要单独产品策略。

## v0.9.1 通用判断力收束

用户明确要求：不要继续为寒香寻、九流门、反救世主、失败者尊严等单个题材写专属规则。长期方案必须能应对复杂输入，而不是无限堆题材补丁。

v0.9.1 因此只收紧 CraftPlan 的通用作词判断：

- **用户强表达优先**：如果用户原句已经有一句值得唱的短语，例如“还是会出手”“不是废物”“眼前的人”，优先保留为声音装置。
- **具体胜过正确**：优先选小动作、物件、口头禅、声音或句式，不把它替换成普通主题词。
- **矛盾胜过顺滑**：保留“不厉害但出手”“轻快但难受”“不想救世但要救眼前人”等内部张力，不抹平成标准正能量主题。
- **副歌必须有功能**：副歌可以重复、变义、反问、回收、反讽、安慰、爆发或沉默，但不能只是放几句漂亮句子。
- **知识库服务歌曲**：知识库只支撑歌曲主线，不能摊成百科点，也不能把用户故事挤掉。
- **曲风不改变世界**：R&B、摇滚、电子等只影响声口、能量和句子颗粒度，不自动带入现代道具和现代场景。
- **粗粝不等于粗口**：可以保留底层噪音、狼狈、混杂和不体面，但不靠明显粗口、廉价狠话或空泛反叛。

v0.9.1 不新增默认调用次数，仍只在 `INSPIRATION` 首轮写词启用 CraftPlan；`LYRICS`、`POLISH`、`CONTINUE` 不启用，避免改坏用户已有歌词或拉长润色耗时。

新增通用压力测试集：

```text
knowledge-base/lyrics-agent-v0.9.1-eval-cases.json
```

评测脚本支持通过 `LYRICS_AGENT_AB_CASES_PATH` 指定该样本集，并在 ignored 的本地报告中输出 `latency_summary`，用于判断 CraftPlan 多一次文本调用的耗时成本是否值得。

## v0.9.1 六条压力测试结论

v0.9.1 已跑 6 条真实 DeepSeek 文本 A/B。完整 Prompt 与完整歌词仍只保存在 ignored 的 `build/reports/lyrics-agent/`；提交区只保留脱敏摘要：

```text
knowledge-base/lyrics-agent-v0.9.1-full6-review-summary.json
```

结果不达标：

- B 组 v0.9.1 明显胜出 `2/6`。
- A 组 v0.7 胜出 `4/6`。
- 其中反宏大守护题存在争议，但即使算作接近，v0.9.1 仍未达到扩大到 12 条的门槛。

耗时判断：

- A 组 total P50 约 `64.7s`。
- B 组 total P50 约 `95.5s`。
- CraftPlan 自身 P50 约 `26.9s`。

质量判断：

- v0.9.1 在“开放曲风但不现代漂移”和“粗粝但不低俗”上更稳。
- v0.9.1 在强用户原句题上仍会犯错：把“还是会出手”“不是废物”替换成新的声音装置，导致作品更设计化但不一定更能唱进用户心里。
- 这说明下一轮不应继续扩样本，也不应继续堆题材规则；应先修 CraftPlan 的第一判断：**用户原句是否已经是最好的 hook / device**。
